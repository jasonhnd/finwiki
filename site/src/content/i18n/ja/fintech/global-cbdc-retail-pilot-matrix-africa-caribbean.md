# 世界のリテール CBDC プログラム比較 — アフリカ、カリブ、アジア、英国

## ウィキ上の位置づけ

この項目は [[fintech/INDEX|fintech index]] の下にあり、ひとまとめにされやすい 7 つの公的通貨または公的決済 project を時点付きで比較する。[[fintech/nigeria-enaira-retail-cbdc|eNaira]]、[[fintech/bahamas-sand-dollar-cbdc|Sand Dollar]]、[[fintech/jamaica-jam-dex-cbdc|JAM-DEX]]、[[fintech/boe-digital-pound-consultation|digital pound]]、[[fintech/ecny-supply-chain-expansion|e-CNY]] とあわせて読む。wholesale project は [[fintech/mbridge-bis-multi-cbdc-overview|mBridge]] と [[fintech/bis-project-agora-overview|Project Agorá]]を参照。

> [!info] 要約
> 7 つの名称は、同じ段階・同じ instrument の 7 つの観測値ではない。Sand Dollar、eNaira、JAM-DEX は発行済み retail CBDC。e-CNY は引き続き pilot・rollout 資料を通じて説明される。ECCB の DCash pilot は 2024 年 1 月 12 日に終了したが、DCash 2.0 に向けた作業は続いた。Bakong は NBC が運営し、銀行と payment-service-provider の口座を接続する payment system であり、直接比較できる中央銀行債務ではない。digital pound は launch 判断のない design project のままである。したがって、比較では legal form、programme stage、distribution model、metric definition を分けなければならない。^[https://cdn.eccb-centralbank.org/documents/2024-07-03-12-52-21-2023-2024-Annual-Report.pdf] ^[https://www.nbc.gov.kh/download_files/publication/annual_rep_eng/AR_ENG_as_of_16.07.25_Clean.pdf] ^[https://www.bankofengland.co.uk/the-digital-pound/progress-update-digital-pound-design-phase]

## 比較方法

snapshot date は 2026 年 7 月 30 日。各行は中央銀行の公式公表資料に基づく。IMF paper は歴史分析に有用だが、日付、単位、分母が明示されない adoption figure は引き継がない。「registered wallet」「linked account」「transaction」「active user」は相互に置き換えられない。

## マトリクス A · プログラム状況

status と launch date は異なる当局に由来するため、表の各行に個別の公式出典を付す。

| プログラム | 2026-07-30 時点の確認済み公開状況 | 出典 |
|---|---|---|
| 🇧🇸 [[fintech/bahamas-sand-dollar-cbdc\|Sand Dollar]] | authorised financial institution を通じた national release を 2020-10-20 に開始。Central Bank は Bahamian digital currency / CBDC と説明 | ^[https://www.centralbankbahamas.com/news/public-notices/the-sand-dollar-is-on-schedule-for-gradual-national-release-to-the-bahamas-in-mid-october-2020] |
| 🇨🇳 e-CNY | public pilot / rollout が継続。公式の累積取引指標は報告されるが、引用した PBoC 資料は単一の「national launch」日を宣言していない | ^[https://www.pbc.gov.cn/xindaishichangsi/5443861/5443865/5443892/5957f8d15a824e9e88d01710873482d3/2025110711361912922.pdf] |
| 🇰🇭 Bakong | 2020-10-20 に開始した NBC 運営 payment system。参加銀行と payment service provider を接続 | ^[https://www.nbc.gov.kh/download_files/publication/annual_rep_eng/AR_ENG_as_of_16.07.25_Clean.pdf] |
| 🇪🇨 DCash | pilot は 2021-03-31 に開始し、34 か月後の 2024-01-12 に終了。ECCB は次の段階を DCash 2.0 への移行と説明 | ^[https://cdn.eccb-centralbank.org/documents/2024-07-03-12-52-21-2023-2024-Annual-Report.pdf] |
| 🇳🇬 [[fintech/nigeria-enaira-retail-cbdc\|eNaira]] | 2021 年に開始した CBN retail CBDC。公式 design paper が operating model と目的を説明 | ^[https://www.cbn.gov.ng/Out/2021/CCD/eNaira%20Design%20Paper.pdf] |
| 🇯🇲 [[fintech/jamaica-jam-dex-cbdc\|JAM-DEX]] | 2022 年に phased rollout。2022 年改正で CBDC を legal tender とし、Bank of Jamaica が sole issuer であることを確認 | ^[https://boj.org.jm/jam-dex-phased-rollout-progresses/] |
| 🇬🇧 [[fintech/boe-digital-pound-consultation\|digital pound]] | design phase は 2026 年に終了。2026 年 3 月 update 時点で導入判断なし | ^[https://www.bankofengland.co.uk/the-digital-pound/progress-update-digital-pound-design-phase] |

従来の「DCash は 2 か月の outage 後に中止」という label は誤解を招いた。2022 年の service interruption は記録されているが、ECCB の 2023–24 annual report は 2024 年 1 月を pilot の計画終了と位置づけ、その後の commercial CBDC deployment に必要な要件を論じている。

## マトリクス B · 法的・通貨的性格

下表は、各当局の資料を使い、中央銀行債務、legal-tender status、payment-system balance、proposal status を区別する。^[https://cdn.centralbankbahamas.com/documents/2021-02-15-11-24-12-Central-Bank-Electronic-Bahamian-Dollars-Regulations-2021.pdf] ^[https://boj.org.jm/jam-dex-phased-rollout-progresses/] ^[https://cdn.eccb-centralbank.org/documents/2024-07-03-13-20-32-Independent-Auditors-Report-and-Financial-Statements---March-2024.pdf] ^[https://www.bankofengland.co.uk/the-digital-pound/progress-update-digital-pound-design-phase]

| プログラム | 公的通貨としての性格 | 重要な境界 |
|---|---|---|
| Sand Dollar | Central Bank が発行し、引用した 2021 regulations の下で legal tender となる electronic Bahamian dollar | 監督対象 wallet provider を通じて流通 |
| e-CNY | PBoC programme の下で発行される renminbi の digital form | pilot scope と累積利用は、別途日付を定めた nationwide launch と同義ではない |
| Bakong | 中央 infrastructure が参加機関とその顧客間の transfer を記録 | すべての linked account balance を NBC 直接発行 CBDC と扱わない |
| DCash | pilot 期間中に ECCB が発行した Eastern Caribbean dollar の digital version | pilot DCash は platform 終了後に legal tender として受け入れられなくなった |
| eNaira | CBN が発行する naira の digital form | 現在の adoption は 2021 design paper とは別の出典で確認する必要がある |
| JAM-DEX | Bank of Jamaica の CBDC かつ legal tender | wallet provider が user へ流通 |
| digital pound | 将来の可能性としての BoE liability | launch 前に肯定的判断と primary legislation が必要 |

この法的分類は、公表定義なしに project を「pure」から「quasi」まで順位づけるより有用である。

## マトリクス C · 発行と流通

下表は、公式 programme document に記載された distribution feature だけを記録する。^[https://www.cbn.gov.ng/Out/2021/CCD/eNaira%20Design%20Paper.pdf] ^[https://www.centralbankbahamas.com/news/public-notices/the-sand-dollar-is-on-schedule-for-gradual-national-release-to-the-bahamas-in-mid-october-2020] ^[https://boj.org.jm/jam-dex-phased-rollout-progresses/] ^[https://cdn.eccb-centralbank.org/documents/2024-07-03-12-52-21-2023-2024-Annual-Report.pdf] ^[https://www.bankofengland.co.uk/the-digital-pound/progress-update-digital-pound-design-phase]

| プログラム | 確認済みの流通構造 |
|---|---|
| Sand Dollar | Central Bank が発行し、authorised financial institution が wallet を提供して CBDC を流通 |
| e-CNY | authorised operator を介する二層 operating model。programme scope は時間とともに変化 |
| Bakong | NBC が core system を運営。参加銀行と payment service provider が customer account・app を接続 |
| DCash | ECCB が pilot DCash を mint し financial institution に発行。機関が consumer または merchant wallet へ transfer |
| eNaira | CBN design は financial institution と wallet を用いる仲介 model |
| JAM-DEX | wallet provider が JAM-DEX を流通。Bank of Jamaica は 2022 phased rollout で Lynk を特定し、後に追加 onboarding activity を掲載 |
| digital pound | 提案中の public-private platform model は引き続き design 中。experiment は最終 architecture を構成しない |

一つの「anchor wallet」が全 programme の adoption を説明するとの因果主張を、出典は裏付けない。commercial incentive は分析し得るが、比較可能な証拠なしに cross-country の測定結果として示してはならない。

## マトリクス D · 本人確認と保有上限

公開された KYC tier と limit は programme 固有で、変更され得る。したがって下表は、異なる日付の根拠のない cap を再掲せず、比較の境界を示す。^[https://cdn.centralbankbahamas.com/documents/2021-02-15-11-24-12-Central-Bank-Electronic-Bahamian-Dollars-Regulations-2021.pdf] ^[https://www.cbn.gov.ng/Out/2021/CCD/eNaira%20Design%20Paper.pdf] ^[https://www.bankofengland.co.uk/the-digital-pound/progress-update-digital-pound-design-phase]

| プログラム群 | 比較できること | 時点付き product または rule 出典が必要なこと |
|---|---|---|
| 発行済み CBDC | 当局は risk-based onboarding と wallet / intermediary control を利用 | 現在の残高、取引、tier limit |
| Bakong | 参加機関が payment-system model の下で customer onboarding を実施 | account class が CBDC wallet tier と比較可能か |
| digital pound | lab experiment は tiered wallet と tourist wallet の concept を test | 最終的な holding limit、KYC tier、production policy |

従来表の Sand Dollar、e-CNY、Bakong、eNaira、digital pound の具体的 cap は、proposal、product rule、出典のない概算を混在させていた。直接の日付付き rule または provider document が得られるまで削除する。

## マトリクス E · 普及に関する証拠

下表は evidence-availability matrix であり、adoption league table ではない。中央銀行 report に基づき、各 metric の粒度を維持する。^[https://www.pbc.gov.cn/xindaishichangsi/5443861/5443865/5443892/5957f8d15a824e9e88d01710873482d3/2025110711361912922.pdf] ^[https://cdn.eccb-centralbank.org/documents/2024-07-03-12-52-21-2023-2024-Annual-Report.pdf] ^[https://www.nbc.gov.kh/download_files/publication/annual_rep_eng/AR_ENG_as_of_16.07.25_Clean.pdf]

| 証拠の種類 | 安全な解釈 |
|---|---|
| PBoC の累積 e-CNY transaction・value | 記載された報告日までの累積 activity を示す。daily-active-user share ではない |
| NBC Bakong account・transaction data | 広範な payment-system network を説明。central-bank-liability wallet adoption と直接比較できない |
| ECCB pilot の operational measure | pilot performance と lesson を説明。platform closure だけで adoption failure metric にはならない |
| Registered wallet count | 当局が activity と unique-user の定義も公表しない限り enrollment measure にすぎない |
| Active wallet / population percentage | period、activity threshold、duplicate-account treatment、denominator が一致する場合のみ比較可能 |

したがって、従来の「Bakong adoption 40–60%」「e-CNY daily active は数百万人規模」、programme 横断の winner / failure ranking は撤回する。共通の metric grain で裏付けられていなかった。

## マトリクス F · 技術と vendor の証拠

下表は、文書で確認できる実装事実と、裏付けのない vendor-performance inference を分ける。^[https://cdn.eccb-centralbank.org/documents/2024-07-03-12-52-21-2023-2024-Annual-Report.pdf] ^[https://www.bankofengland.co.uk/the-digital-pound/lab]

| 問い | 証拠ルール |
|---|---|
| 特定技術 supplier | 当該 deployment に関する中央銀行の procurement、contract、programme announcement を引用 |
| Ledger design | 日付付き technical paper を引用。marketing shorthand から特定の open-source stack を推定しない |
| Operational incident | 当局の incident report または annual report を引用し、incident duration と programme outcome を分ける |
| Vendor と adoption の因果関係 | 比較可能な multi-programme evidence が必要。supplier の共通性は原因の証明ではない |
| Digital-pound technology | lab component は demonstration。Bank は DLT を design の一部とするか未決定と説明 |

従来の「Bitt cluster 対 eCurrency winner」比較は削除した。不完全な vendor fact と出典のない adoption ranking を組み合わせ、公式 report が立証しない因果関係を示唆していた。

## クロスボーダーの境界

cross-border link は rail ごとに評価する必要がある。香港 e-CNY/FPS arrangement は retail cross-boundary service、mBridge は wholesale platform、Bakong の二国間・地域 QR connection は payment-system interoperability である。これらを一つの「CBDC integration」件数にまとめてはならない。[[fintech/ecny-supply-chain-expansion|e-CNY update]]、[[fintech/mbridge-bis-multi-cbdc-overview|mBridge]]、NBC annual report を参照。^[https://www.hkma.gov.hk/eng/news-and-media/press-releases/2024/05/20240517-4/] ^[https://www.bis.org/about/bisih/topics/cbdc/mcbdc_bridge.htm] ^[https://www.nbc.gov.kh/download_files/publication/annual_rep_eng/AR_ENG_as_of_16.07.25_Clean.pdf]

一つの出典に link がないことは、programme に「存在しない」との証明ではない。現在の corridor claim には、counterpart、service、launch state、official source を明記すべきである。

## 分析での利用

訂正後の matrix は、根拠を示せる次の 4 問を支える。

1. instrument は発行済みの public money、deposit の payment-system representation、終了した pilot、proposal のどれか。
2. どの institution が流通させ、どの entity が user relationship を負うか。
3. 報告数値は cumulative transaction、wallet、linked account、active user、population share のどれか。
4. cross-border connection は retail、wholesale、bilateral QR interoperability、experiment のみ、のどれか。

これらの問いにより、有用な比較構造を維持しながら誤った ranking を防げる。
