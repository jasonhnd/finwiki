# 必須検証経路の統一

## 日本語

### 公開範囲

- Issue #184 の Bun runtime pin、canonical verification command、実行可能な pre-push hook、pull request / GitHub Pages / Vercel workflow、必須 publish route check、運用文書、三言語 README / CHANGELOG / release note と生成 public snapshot。
- 全 assembled HTML href の crawl と既知 19 broken links の修正は Issue #183 の別 scope です。

### 主要変更

- Bun 1.3.14 を `.bun-version` と root `packageManager` に固定し、GitHub Actions の全 workflow を同じ version file へ接続しました。
- `bun run verify` に frozen install、release / docs / surface / AI / strict i18n / index / wiki audit、production dependency audit、Astro typecheck、全 test、Astro / Pagefind build、safe assembly、13 required routes と diff check を統合しました。従来 report-only の i18n status には明示的な fail mode を追加しました。
- local pre-push hook を executable にし、pull request required workflow、GitHub Pages、Vercel が同じ runner を実行する構成にしました。Vercel install / build は official pin pattern の `bunx bun@1.3.14` を明示します。

### 検証結果

- `bun run verify --out _site` は Bun 1.3.14 と frozen lockfile を確認し、release / docs / generated surface / AI / i18n / index / wiki gate と production vulnerability 0 件を通過しました。
- Astro typecheck は 39 files、0 errors、0 warnings、5 hints。root `bun test` は 6 files / 35 tests / 122 assertions、fail 0。Astro build は 2,969 pages、duplicate HTML ID は 0、Pagefind は 2,968 pages を index しました。
- Pages artifact は Astro 6,258 files と raw public 3,062 files を組み立て、root、ja/en、AI / API、crawler、Pagefind を含む 13 required routes がすべて PASS しました。stale count、missing translation、type error、missing `/en/` と empty `llms.txt` の negative fixture は意図どおり canonical gate を fail しました。

### 既知の注意点

- GitHub `main` は現時点で branch protection / ruleset がなく、required check は workflow が base branch に入り green context を作るまで安全に強制できません。Issue #184 はその repository-setting evidence が揃うまで close しません。
- branch は #185、#186、#177 の dependency chain に積み重なっています。依存 commit が `pre` に入るまでは重複 PR を開きません。

### 次の作業

- dependency chain merge 後に最新 `pre` へ重ね直し、fresh PR で `Required verification` を通過させます。その後 `main` ruleset に pull request と同 check を必須化し、direct unverified update が拒否される証拠を Issue #184 に記録します。self-merge / self-close は行いません。

## English

### Release Scope

- Issue #184 Bun runtime pin, canonical verification command, executable pre-push hook, pull-request / GitHub Pages / Vercel workflows, required publish-route check, operations documentation, trilingual README / CHANGELOG / release note, and generated public snapshot.
- Crawling every assembled HTML href and fixing the known 19 broken links remain the separate scope of Issue #183.

### Major Changes

- Pinned Bun 1.3.14 in `.bun-version` and the root `packageManager`, then connected every GitHub Actions workflow to that version file.
- Consolidated frozen install; release, docs, surface, AI, strict i18n, index, and wiki audits; production dependency audit; Astro typecheck; all tests; Astro/Pagefind build; safe assembly; 13 required routes; and the diff check under `bun run verify`. Added an explicit failure mode to the formerly report-only i18n status tool.
- Made the local pre-push hook executable and configured the pull-request required workflow, GitHub Pages, and Vercel to execute the same runner. Vercel install/build explicitly use the official `bunx bun@1.3.14` pin pattern.

### Validation Results

- `bun run verify --out _site` confirmed Bun 1.3.14 and the frozen lockfile, then passed the release, docs, generated-surface, AI, i18n, index, and wiki gates with zero production vulnerabilities.
- Astro typecheck completed across 39 files with 0 errors, 0 warnings, and 5 hints. Root `bun test` passed 35 tests / 122 assertions across six files with zero failures. Astro built 2,969 pages, duplicate HTML IDs remained zero, and Pagefind indexed 2,968 pages.
- The Pages artifact assembled 6,258 Astro files plus 3,062 raw public files. All 13 required routes for root, ja/en, AI/API, crawler, and Pagefind surfaces passed. Negative cases for a stale count, missing translation, type error, missing `/en/`, and empty `llms.txt` failed the canonical gate as intended.

### Known Notes

- GitHub `main` currently has no branch protection or ruleset. The required check cannot be enforced safely until the workflow reaches the base branch and creates a green check context. Issue #184 will remain open until repository-setting evidence is recorded.
- This branch is stacked on the #185, #186, and #177 dependency chain. No duplicate PR will be opened until those prerequisite commits enter `pre`.

### Next Steps

- After the dependency chain merges, replay onto the latest `pre` and pass `Required verification` in a fresh PR. Then require pull requests and that check in the `main` ruleset, and record evidence that direct unverified updates are rejected in Issue #184. Do not self-merge or self-close.
