# エントリ発見グラフのビルド最適化

## 日本語

### 公開範囲

- Issue #195 の article-end discovery cache invalidation と build-time full-corpus rescan を修復する。
- 対象は `entryDiscovery.mjs`、entry static-path generation、`EntryLayout.astro` integration、focused tests、architecture / FSD / RTM、三言語 README、CHANGELOG と release state。
- wiki corpus の facts、翻訳本文、discovery card の表示順・上限・CSS、wikilink / backlink semantics は変更しない。

### 主要変更

- `count:first:last` cache key を、全 entry の normalized route、domain、slug、title、tags、ordered `related` targets と loader-provided body を length-prefixed serialization して得る SHA-256 fingerprint に置換した。中間 entry の behavior-affecting change でも graph を失効させる。
- canonical entries から immutable route graph を entry `getStaticPaths()` で一度だけ構築し、各言語・各 route の完成済み discovery payload を page props で渡す。`EntryLayout` から per-page `getCollection('entries')` と full-corpus sort / scan を除去した。
- explicit related → backlinks → shared tags → deterministic read-next → sibling fallback の優先順、related 5 / next 3 / backlinks 5 の上限、localized preview filtering と empty-lane omission を維持した。

### 検証結果

- focused cache / parity suite は 4 tests / 22 assertions、全 repository suite は 86 tests / 294 assertions で PASS。Astro check は 44 files / 0 errors / 0 warnings / 0 hints、duplicate-ID audit は 2,969 pages / issues 0。
- 同じ warmed content-cache と empty-`dist` 条件で 2,969-page clean build は 51.21 秒から 21.18 秒へ 30.03 秒、58.6% 短縮した。static-route generation は 37.42 秒から 7.78 秒へ 79.2% 短縮した。
- 変更前後の 2,884 localized entry pages から article-end discovery fragment を抽出して byte comparison し、差分 0 を確認した。
- full canonical `bun run verify --out _site` は、release docs 20 files / 18 strict notes / 76 grandfathered notes、wiki 1,489 entries / issues 0 / canonical drift 0、generated API 1,482 entries / fixed-timestamp byte identity / leakage 0、ja / en 各 1,442 current mirrors、production vulnerability 0、Pagefind 2,968 pages、assembly 6,258 Astro files + 3,077 raw files、13 required routes、final HTML audit 5,864 routes、generated URL audit 6,041 unique internal URLs、`git diff --check` を含む全 gate で PASS した。

### 既知の注意点

- cache は一つの static build process 内だけで有効であり、persistent cross-build artifact は作らない。
- backlink index は引き続き resolved wikilink から一度だけ構築する。本 release は resolution semantics や card output を変更しない。
- Issue #192 の advisory truthfulness queue と Issue #193 の `.opinions/**` public-boundary decision は別 scope のままである。

### 次の作業

- current head で real pre-push と PR Required Verification / Dependency Audit / Vercel を通す。
- verified PR を `pre` へ merge し、承認済み promotion で `main` へ反映後、同じ main merge SHA に tag / GitHub Release `v2026.07.29` を作成する。
- production build timing を監視し、#192 の bounded review packets を継続する。#193 は maintainer の binary policy choice 後にのみ実行する。

## English

### Release Scope

- Fix the article-end discovery cache invalidation and build-time full-corpus rescans tracked by Issue #195.
- Scope covers `entryDiscovery.mjs`, entry static-path generation, `EntryLayout.astro` integration, focused tests, architecture/FSD/RTM docs, the trilingual README, CHANGELOG, and release state.
- Wiki-corpus facts, translation bodies, discovery-card ordering/limits/CSS, and wikilink/backlink semantics are unchanged.

### Major Changes

- Replaced the `count:first:last` cache key with a SHA-256 fingerprint over length-prefixed normalized route, domain, slug, title, tags, ordered `related` targets, and any loader-provided body for every entry. Behavior-affecting changes to intermediate entries now invalidate the graph.
- Build one immutable route graph from canonical entries in entry `getStaticPaths()`, then pass completed discovery payloads for each language and route through page props. Removed per-page `getCollection('entries')` and full-corpus sorting/scanning from `EntryLayout`.
- Preserved the explicit-related → backlinks → shared-tags → deterministic-read-next → sibling-fallback priority, the 5/3/5 lane limits, localized-preview filtering, and empty-lane omission.

### Validation Results

- The focused cache/parity suite passed 4 tests / 22 assertions; the complete repository suite passed 86 tests / 294 assertions. Astro check passed across 44 files with 0 errors / 0 warnings / 0 hints, and the duplicate-ID audit reported zero issues across 2,969 pages.
- Under the same warmed content-cache and empty-`dist` conditions, the clean 2,969-page build fell from 51.21 seconds to 21.18 seconds, a 30.03-second or 58.6% reduction. Static-route generation fell from 37.42 seconds to 7.78 seconds, a 79.2% reduction.
- Extracted and byte-compared the article-end discovery fragment from all 2,884 localized entry pages before and after the change; differences were zero.
- Full canonical `bun run verify --out _site` passed every gate, including 20 release-doc files / 18 strict notes / 76 grandfathered notes; 1,489 wiki entries / zero issues / zero canonical drift; 1,482 generated API entries / fixed-timestamp byte identity / zero leakage; 1,442 current mirrors per language; zero production vulnerabilities; 2,968 Pagefind pages; assembly of 6,258 Astro files plus 3,077 raw files; all 13 required routes; 5,864 final HTML routes; 6,041 unique generated internal URLs; and `git diff --check`.

### Known Notes

- The cache exists only within one static-build process; it creates no persistent cross-build artifact.
- The backlink index is still built once from resolved wikilinks. This Release does not change resolution semantics or card output.
- The advisory truthfulness queue in Issue #192 and the `.opinions/**` public-boundary decision in Issue #193 remain separate scopes.

### Next Steps

- Pass the real pre-push hook and PR Required Verification / Dependency Audit / Vercel on the current head.
- Merge the verified PR into `pre`, promote it to `main` through the approved flow, then create tag and GitHub Release `v2026.07.29` on the same main merge SHA.
- Monitor production build timing, continue bounded #192 review packets, and implement #193 only after the maintainer makes its binary policy choice.
