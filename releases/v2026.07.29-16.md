# 暗号資産取引所・カストディの表出典123件を校正

## 日本語

### 公開範囲

- Issue #237 の released-main `cbb7f739` baseline にある 123 table-related warnings / 81 `exchanges/` source paths を bounded scope とする。
- 内訳は 105 `table_without_provenance` + 18 `table_row_without_marker` である。
- 81 source entries、対応する ja / en 162 mirrors、三言語 release / operating surfaces、root index / AI discovery surfaces を同じ release unit で同期する。
- `.opinions/**`、`docs/**`、人手判断を待つ Issue #193、後続 Issue #238–#244、非 owned exchange paths は変更しない。

### 主要変更

- 規制当局の registry / warning、運営会社の公式 disclosure / product terms、incident / restructuring disclosure を table / row scope ごとに結び、generic homepage や aggregator だけで動的比較を cover しない形へ校正した。
- brand、運営法人、登録主体、service availability、legacy / exited status を分離し、名称変更、事業移管、撤退、M&A の発生日・完了日・条件を区別した。
- exchange / custody comparison では、法的 perimeter、基準日、開示単位を揃え、裏付けのない global rank、volume、market share、対応資産数、固定 fee / latency、insurance / custody guarantee を確定事実から除いた。
- hack、bankruptcy、規制 warning、利用制限、whitelist / listing の履歴を、公式 record が支える entity、jurisdiction、日付、status に限定した。
- ja / en mirrors では、法人名、registration / warning status、日付、金額・比率、否定・条件表現、URL、wikilink、table / list shape を source correction と同じ意味へ同期した。

### 検証結果

- baseline `bun run provenance:audit -- --json` は full 1,395 warnings、Issue #237 owned 123 / 81 paths = 105 table-level + 18 mixed-row を再現した。
- fresh audit は full 1,272 warnings = 1,223 table-level + 49 mixed-row、Issue #237 owned 0 / 0 paths。81 source / 162 mirrors の semantic / structural parity、ja / en 各 1,442 current・stale / orphaned / missing 0、factual consistency 0 を確認した。
- `audit:all --as-of 2026-07-29` は blocking rows 0（queue-growth monitor 1 は advisory）、`wiki:audit:ci` は 1,489 entries / issues 0 / dead links 0 / canonical drift 0。`release:write` は 1,606 Markdown / 1,605 public pages / 1,482 sitemap・API entries を生成した。
- full `bun run verify --out _site` は 98 tests、2,969 built pages、2,968 Pagefind pages、type errors 0、production dependency vulnerabilities 0、final route / discovery issues 0 で PASS。`git diff --check` も PASS。real pre-push も同じ required verification を再実行して PASS した。

### 既知の注意点

- provenance audit は read-only / advisory であり、123 warnings の解消は corpus 全体または各 entry の全 prose を一括保証しない。実証範囲は owned tables / rows と修正に必要な直近 context である。
- registry、warning、service availability、supported assets、volume、market share、fee、incident status は jurisdiction と基準日により変動する。日付と適用範囲を保ち、現在値として一般化しない。
- 動的 page、login を要する product surface、automated-request restriction は、公開された regulator / operator record の不存在と同一視しない。

### 次の作業

- work branch を `pre` へ merge し、承認済み promotion PR で `pre` を `main` へ merge する。
- production deployment と同じ main merge SHA に tag / GitHub Release `v2026.07.29-16` を作成する。
- Issue #237 に exact audit、source / mirror / gate / deployment / release evidence を記録して close し、親 Issue #192 と次の Issue #238 を更新する。

## English

### Release Scope

- Use the 123 table-related warnings across 81 `exchanges/` source paths in Issue #237's released-main `cbb7f739` baseline as the bounded scope.
- The distribution is 105 `table_without_provenance` plus 18 `table_row_without_marker` findings.
- Synchronize 81 source entries, 162 corresponding ja/en mirrors, trilingual release / operating surfaces, and root-index / AI-discovery surfaces in one release unit.
- Leave `.opinions/**`, `docs/**`, human-review Issue #193, downstream Issues #238–#244, and non-owned exchange paths unchanged.

### Major Changes

- Tied regulator registries and warnings, operator disclosures and product terms, and incident or restructuring disclosures to table or row scope instead of treating a generic homepage or aggregator as blanket support for a dynamic comparison.
- Separated the brand, operating legal entity, registered entity, service availability, and legacy or exited status; distinguished announcement, completion, and conditional dates for renames, transfers, exits, and M&A.
- Aligned legal perimeter, evidence date, and disclosed unit in exchange and custody comparisons; removed unsupported global ranks, volumes, market shares, supported-asset counts, fixed fees or latency, and insurance or custody guarantees from established facts.
- Limited hack, bankruptcy, regulatory-warning, access-restriction, and whitelist or listing histories to the entity, jurisdiction, date, and status supported by official records.
- Synchronized legal names, registration and warning status, dates, amounts and ratios, negation, conditional language, URLs, wikilinks, and table or list shape across the ja/en mirrors.

### Validation Results

- Baseline `bun run provenance:audit -- --json` reproduces 1,395 full warnings and 123 Issue #237 owned warnings across 81 paths, comprising 105 table-level plus 18 mixed-row findings.
- The fresh audit reports 1,272 full warnings, comprising 1,223 table-level plus 49 mixed-row findings, and zero Issue #237 owned warnings across zero paths. Semantic and structural parity passed for 81 sources and 162 mirrors; each locale has 1,442 current mirrors, zero stale / orphaned / missing entries, and factual consistency reports zero problems.
- `audit:all --as-of 2026-07-29` reports zero blocking rows (one queue-growth monitor remains advisory); `wiki:audit:ci` reports 1,489 entries, zero issues, zero dead links, and zero canonical drift. `release:write` generated 1,606 Markdown files, 1,605 public pages, and 1,482 sitemap / API entries.
- Full `bun run verify --out _site` passed with 98 tests, 2,969 built pages, 2,968 Pagefind pages, zero type errors, zero production dependency vulnerabilities, and zero final-route or discovery issues. `git diff --check` also passes. The real pre-push hook repeated the same required verification and passed.

### Known Notes

- The provenance audit remains read-only and advisory. Eliminating 123 warnings is not a blanket guarantee for the corpus or every paragraph in each entry; the evidenced scope is the owned tables or rows and immediate context required for correction.
- Registries, warnings, service availability, supported assets, volume, market share, fees, and incident status vary by jurisdiction and evidence date. Dates and applicability boundaries remain explicit rather than being generalized as current values.
- A dynamic page, login-gated product surface, or automated-request restriction is not treated as equivalent to the absence of a public regulator or operator record.

### Next Steps

- Create tag / GitHub Release `v2026.07.29-16` on the same main merge SHA as the production deployment.
- Close Issue #237 with exact audit, source / mirror / gate / deployment / release evidence; update parent Issue #192 and activate Issue #238.
