# 財務・不動産金融の表出典233件を校正

## 日本語

### 公開範囲

- Issue #238 の released-main `c6ba268f` baseline にある 233 `table_without_provenance` warnings / 49 source paths を bounded scope とする。
- 内訳は `finance/` 23 paths / 116 warnings と `real-estate-finance/` 26 paths / 117 warnings である。
- 49 source entries、対応する ja / en 98 mirrors、三言語 release / operating surfaces、root index / AI discovery surfaces を同じ release unit で同期する。
- `.opinions/**`、`docs/**`、人手判断を待つ Issue #193、後続 Issue #239–#244、非 owned paths は変更しない。

### 主要変更

- 法令上の閾値、comply-or-explain、公布済み規則、working-group roadmap、市場慣行、分析上の仮定を分離し、TOB、SSBJ 開示、TCFD、merger control、MBO / squeeze-out の日付・適用範囲・手続を一次資料へ揃えた。
- WACC、LTV、DSCR、IRR、fee、tenor、cap rate、capital stack を普遍的な市場値として扱わず、公式開示がない数値は illustrative scenario、issuer-specific term、または検証 checklist として明示した。
- J-REIT の investment-unit holdings、market capitalization、AUM、DPU、occupancy、LTV、tenant / master-lessee concentration を、基準日、分母、直接 / 間接保有、契約上の相手方と最終利用者に分けて校正した。
- sponsor と current control の境界、海外物件の保有、issuer-specific asset-management fee、appraisal と取引価格の違い、上場 / 私募 REIT の流動性・費用・開示条件を公式 issuer / JPX / regulator record に合わせた。
- ja / en mirrors では、法的主体、制度 status、日付、金額・比率、否定・条件表現、URL、wikilink、table / list shape を source correction と同じ意味へ同期した。

### 検証結果

- baseline `bun run provenance:audit -- --json` は full 1,272 warnings、Issue #238 owned 233 / 49 paths を再現した。
- scoped audit は Issue #238 owned warnings を 0 / 0 paths にし、full residual を 1,039 warnings = 990 `table_without_provenance` + 49 `table_row_without_marker` とした。
- 最終 bounded diff は 49 source / 98 mirrors の semantic / structural parity、ja / en 各 1,442 current（stale / orphaned / missing 0）、blocking factual rows 0、wiki 1,489 entries / issues 0 を PASS した。`release:write` は 1,607 Markdown files / 1,606 public pages / 1,482 sitemap・API entries を同期し、full verification は 98 tests / 327 assertions、2,969 built pages、2,968 Pagefind pages、dependency vulnerabilities / Astro diagnostics / final-route / discovery issues 0、`git diff --check` PASS で完了した。

### 既知の注意点

- provenance audit は read-only / advisory であり、233 warnings の解消は corpus 全体または各 entry の全 prose を一括保証しない。実証範囲は owned tables と修正に必要な直近 context である。
- 規制、issuer metrics、REIT 銘柄数、portfolio、holding / trading flow、金利、cap rate、fee、tenor は基準日や契約により変わる。日付、分母、法域、契約主体を保ち、現在値または普遍的条件として一般化しない。
- model output と scenario sensitivity は観測済み市場条件ではない。入力値、attach / detach point、recourse、security、bankruptcy-remoteness の成立条件を案件別に確認する必要がある。

### Release Scope

- Use the 233 `table_without_provenance` warnings across 49 source paths in Issue #238's released-main `c6ba268f` baseline as the bounded scope.

### Major Changes

- Separated statutory thresholds, comply-or-explain requirements, promulgated rules, working-group roadmaps, market practice, and analytical assumptions; aligned TOB, SSBJ disclosure, TCFD, merger-control, MBO, and squeeze-out dates, applicability, and procedures to primary sources.

- Aligned sponsor and current-control boundaries, overseas-property ownership, issuer-specific asset-management fees, appraisal versus transaction price, and listed/private-REIT liquidity, cost, and disclosure conditions to official issuer, JPX, and regulator records.
- Synchronized legal entities, regime status, dates, amounts and ratios, negation, conditional language, URLs, wikilinks, and table or list shape across the ja/en mirrors.

### Known Notes

- The provenance audit remains read-only and advisory. Eliminating 233 warnings is not a blanket guarantee for the corpus or every paragraph in each entry; the evidenced scope is the owned tables and the immediate context required for correction.
- Regulations, issuer metrics, REIT counts, portfolios, holdings and trading flows, rates, cap rates, fees, and tenor vary by evidence date and contract. Dates, denominators, jurisdictions, and contractual parties remain explicit rather than being generalized as current or universal terms.
- Model outputs and scenario sensitivities are not observed market conditions. Inputs, attachment and detachment points, recourse, security, and bankruptcy-remoteness conditions require deal-specific verification.
