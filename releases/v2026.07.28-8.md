## English

### Release Scope

- Issue #190's current `canonical_anchor` contract, mirror policy, cross-domain anchor convention, developer-documentation entry point, the trilingual README/CHANGELOG, this release note, and public discovery surfaces synchronized by the release generator.
- Factual wiki-entry bodies, `ja` / `en` translation mirrors, the domain map, and public URLs are unchanged.

### Major Changes

- Aligned the root schema, architecture documentation, and policy pages on the current contract: `canonical_anchor` is required on true mirrors, omitted from anchors and ordinary related pages, declared target resolution/core-body linkage/zero drift are release-gated, and semantic mirror classification plus reverse links remain editorial review.
- Marked the pre-implementation proposal as a historical decision record and consolidated current authority in `SCHEMA.md`, ADR-007, and the entry-authoring checklist.
- Added the 11 previously unlisted active developer documents to `docs/README.md`, making every active document reachable from the sole developer-documentation entry point. Current wording left over from the JapanFG split was updated to role-specific institution domains.

### Validation Results

- `bun run docs:audit`: passed.
- `bun run docs:stale`: passed across 66 active documents / 16 checks with zero stale references.
- `git diff --check`: passed.
- `bun run verify --out _site`: passed with 82 tests / 272 assertions, Astro check across 44 files with 0 errors / 0 warnings / 0 hints, 2,969 Astro pages, 2,884 entry-metadata pages with zero issues, a final HTML audit across 5,864 routes, a generated URL audit across 6,037 unique URLs, and zero production vulnerabilities.
- Generated-surface drift passed with 1,482 API entries, fixed-timestamp byte identity, and zero docs/audit-artifact/local-path leakage.

### Known Notes

- Tooling fail-closes mechanical drift for a declared `canonical_anchor`, but deciding whether a page is semantically a mirror and checking the anchor-to-mirror reverse link remain editorial-review responsibilities.
- This is a documentation-contract repair; it does not reclassify existing entries' canonical designations or public facts.
- A GitHub Release is created or updated only when publishing `main`; this `pre` repair does not create one.
