# 定期監査の履歴比較と集計精度の修復

## 日本語

### 公開範囲

- Issue #191 の truthfulness audit runner、scheduled GitHub Actions workflow、summary schema、historical fixtures / tests、NFR / RTM / architecture / toolchain / QA / operations docs、三言語 README / CHANGELOG、本 release note、および release generator が同期する公開 discovery surface。
- wiki entry の事実本文、翻訳 mirror、truthfulness audit の検出 heuristic、release hard gate は変更しない。

### 主要変更

- `audit_runner.ts` に `--history-dir` を追加し、prior `summary.json` を再帰読込して直前 2 cycle と current run の bounded trend を作るようにした。actionable freshness row が 2 cycle 連続で増加した場合だけ advisory growth threshold を `tripped` にする。
- factual consistency の repeated `needs_review` group は top-level `row.path` だけでなく `left.path` / `right.path` の両 source を数え、複数 source にまたがる group を正しく advisory `tripped` とする。
- scheduled workflow に read-only `actions: read` を与え、直前 2 回の成功 scheduled artifact を temporary history directory へ download して runner に渡す。summary には日付と count だけを残し、artifact path / machine-local path は残さない。
- Bun 1.3.14 の synchronous pipe が大きな stdout を 768 KiB で truncate する実在 failure を修復した。child audit JSON は専用 temporary file に capture し、process exit 後に完全読込してから削除する。
- observed 49 → 415 → 417 freshness trend、two-cycle trip / reset、insufficient-history monitor、left/right path count、大 stdout、path isolation、workflow wiring を focused fixtures で固定した。

### 検証結果

- `bun test tools/audit_runner.test.ts` は 8 tests / 21 assertions で通過した。
- historical `bun run audit:all --history-dir tools/fixtures/audit-history --as-of 2026-07-14` は実 repository で完走し、current actionable 416、trend 49 → 415 → 416、growth `tripped`、repeated consistency groups 8 を報告した。fixture 自体は acceptance の 49 → 415 → 417 と +366 / +2 を再現した。
- 2.6 MiB の current provenance JSON と、120,000-row synthetic JSON は truncate せず parse できた。workflow YAML は parser を通過した。
- post-source-commit release regeneration に対する full `bun run verify --out _site` は、58 tests / 195 assertions、Astro check 39 files / 0 errors / 0 warnings / 5 hints、Astro 2,969 pages、duplicate ID 0、Pagefind 2,968 pages、assembly 6,258 Astro files + 3,065 raw files、13 required routes、6,029 unique internal URLs、production vulnerability 0 で通過した。

### 既知の注意点

- threshold は advisory のままであり、workflow failure、issue 自動作成、corpus edit、fact verified 化には接続しない。
- scheduled history が 2 件未満なら growth status は `monitor` のままになる。artifact retention や初回 run の情報不足を誤って `not_tripped` としないための動作である。
- GitHub Release は `main` publish 時にのみ作成または更新する。この `pre` 向け修復では作成しない。

### 次の作業

- real pre-push、remote HEAD、PR checks を確認して Issue #191 に closeout evidence を記録し、maintainer review を待つ。self-merge / self-close はしない。

## English

### Release Scope

- Issue #191 truthfulness audit runner, scheduled GitHub Actions workflow, summary schema, historical fixtures/tests, NFR/RTM/architecture/toolchain/QA/operations docs, trilingual README/CHANGELOG, this release note, and public discovery surfaces synchronized by the release generator.
- Factual wiki-entry bodies, translation mirrors, truthfulness-audit detection heuristics, and the release hard gate are unchanged.

### Major Changes

- Added `--history-dir` to `audit_runner.ts`. It recursively loads prior `summary.json` files and builds a bounded trend from the two latest prior cycles plus the current run. The advisory growth threshold trips only when actionable freshness rows increase in two consecutive cycles.
- Repeated factual-consistency `needs_review` groups now count both `left.path` and `right.path`, not only top-level `row.path`, and correctly trip the advisory multi-source pattern threshold.
- Granted the scheduled workflow read-only `actions: read`, downloaded the two latest successful scheduled artifacts into a temporary history directory, and passed that directory to the runner. Summaries retain dates and counts only, never artifact or machine-local paths.
- Repaired a real Bun 1.3.14 failure where synchronous pipes truncated large stdout at 768 KiB. Child audit JSON is captured in a private temporary file, read completely after process exit, and then removed.
- Added focused fixtures for the observed 49 → 415 → 417 freshness trend, two-cycle trip/reset, insufficient-history monitoring, left/right path counting, large stdout, path isolation, and workflow wiring.

### Validation Results

- `bun test tools/audit_runner.test.ts` passed with 8 tests / 21 assertions.
- Historical `bun run audit:all --history-dir tools/fixtures/audit-history --as-of 2026-07-14` completed against the real repository and reported current actionable 416, trend 49 → 415 → 416, growth `tripped`, and eight repeated consistency groups. The fixture itself reproduces the accepted 49 → 415 → 417 sequence and +366 / +2 changes.
- The current 2.6 MiB provenance JSON and a synthetic 120,000-row JSON payload parsed without truncation. The workflow YAML passed parser validation.
- Full `bun run verify --out _site` against the post-source-commit release regeneration passed with 58 tests / 195 assertions, Astro check across 39 files with 0 errors / 0 warnings / 5 hints, 2,969 Astro pages, zero duplicate IDs, 2,968 Pagefind pages, 6,258 Astro files plus 3,065 raw files in the assembled artifact, all 13 required routes, 6,029 unique internal URLs, and zero production vulnerabilities.

### Known Notes

- Thresholds remain advisory and do not fail the workflow, create issues, edit the corpus, or mark facts verified.
- With fewer than two scheduled history artifacts, growth remains `monitor`. This avoids treating missing retention or first-run history as `not_tripped`.
- A GitHub Release is created or updated only when publishing `main`; this `pre` repair does not create one.

### Next Steps

- Confirm the real pre-push, remote HEAD, and PR checks, attach closeout evidence to Issue #191, and wait for maintainer review. Do not self-merge or self-close.
